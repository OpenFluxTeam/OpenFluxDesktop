## Что это

[OpenFlux](https://github.com/OpenFluxTeam/OpenFlux) — инструмент исследования сетевого стека: туннель IPv4 TCP/UDP с подключаемыми транспортами (включая подписанный JS-движок для написания новых), пакетный кодек с zstd и два бэкенда выходной ноды (L3 — прямая пересылка пакетов, L4 — прокси на gVisor).

OpenFluxDesktop — его клиент для компьютера. Ядро идёт в комплекте, работает отдельным процессом и управляется по IPC; приложение ведёт профили, транспорты, ключи и выходные ноды.

```
программы ──> Wintun / utun  или  SOCKS5 / HTTP ──> ядро OpenFlux ──> сессия транспортов ──> выходная нода ──> Интернет
                                                    (в комплекте)     приоритеты, переключение  --mode l4 | l3
```

## Возможности

### Туннель

- **Весь трафик** через виртуальный сетевой интерфейс: Wintun в Windows, utun в macOS (нужны права администратора).
- **Режим прокси**: локальные SOCKS5 (`127.0.0.1:1080`) и HTTP (`127.0.0.1:1081`) для программ, которые вы на них направите. В Windows приложение может на время подключения выставить системный прокси (WinInet).
- **IPv4 TCP и UDP**; через ноду L3 — IP-пакеты целиком, включая ICMP.

### Транспорты и сессии

- **Встроенные транспорты** ядра: Яндекс Документы, Яндекс Volga, Яндекс Доска, Mail.ru, cups.online, Телемост, Avito, MAX/OneMe и `direct` — обычное TCP-соединение с вашей нодой.
- **JS-транспорты**: подписанные пакеты для скриптового движка ядра, ставятся из комплекта, с GitHub или по ссылке. Ядро проверяет подпись каждого пакета; приложение показывает его параметры и отправляет пакет на ваши ноды.
- **Сессии из нескольких транспортов**: в профиле несколько транспортов, у каждого приоритет и сети, где ему можно работать. Согласование аутентифицировано; если активный канал встал, сессия переходит на следующий, не разрывая туннель.
- **Сначала прямое подключение**: пока `direct` до ноды жив, трафик идёт по нему раньше документов — с MTU туннеля 16000 байт, пулом буферов и Reno на его потоках.
- **Группы полос**: несколько каналов одного или разных типов работают как одна полоса, по дорожке на канал.
- **Кодек** на профиль: пакетный с zstd или прежний LZ4 по пакету для старых нод.

### Шифрование

- **AES-256-GCM сквозь** — от клиента до выходной ноды, ключ на канал. С ключом сервис, который несёт документы, видит только шифротекст.
- Ключи нод создаёт мастер; они передаются внутри ссылки на профиль и никуда больше не уходят.

### Выходные ноды

- **Мастер ноды по SSH**: ставит выходную ноду ядра на сервер (Linux amd64, arm64, armv7) и задаёт ей бэкенд и транспорты:
  - **L4** — TCP/IP-стек gVisor в пространстве пользователя: завершает соединения и открывает новые; root не нужен, работает везде;
  - **L3** — пересылка IP-пакетов как есть через SNAT/DNAT, одно соединение из конца в конец; нужны root и iptables.
- **Проверка**: после установки приложение подключается через новую ноду и проверяет, что адрес выхода — адрес сервера.
- **Каналы сервера**: список, смена транспортов (ключ, порт и контекст сохраняются), поделиться, удалить, добавить.
- **Совсем без сервера**: выходом может быть небольшая программа на PHP на обычном веб-хостинге.
- **Ноды обновляются сами**: нода скачивает новые релизы, сверяет их с `SHA256SUMS` и откатывается, если новая сборка не запустилась.
- **Этот компьютер как выход**: режим *Выходная нода* делает приложение нодой, через которую подключаются другие клиенты (L4, или L3 с WinDivert в Windows).

### Ещё

- **Ссылки `openflux://` и QR-коды** несут профиль целиком: транспорты, приоритеты, ключ, кодек.
- **Встроенный браузер** (Chromium вне экрана через KCEF, около 230 МБ, скачивается при первом обращении) для проверок, которые просят некоторые сервисы, например SmartCaptcha или стена входа.
- **Журнал ядра** с уровнями отладки, прямо в приложении.
- **Обновления** из релизов GitHub, со сверкой с `SHA256SUMS.txt` релиза, ставятся только с вашего согласия.
- **Аккаунт openflux.dev** для подписок — по желанию; всё перечисленное работает и без него.

## Что нового в текущем релизе

Релиз **3.9** идёт с ядром OpenFlux 0.14.0 (выходная нода `node-v1.7.0`).

- **Сначала прямое подключение**: обычное TCP-соединение с нодой используется раньше документов, пока оно живо.
- **Скорость**: MTU туннеля 16000 байт на direct с откатом по ICMP «нужна фрагментация», пул буферов отправки, zstd только где он помогает (никогда поверх TLS на direct), Reno на прямых потоках.
- **Группы полос** в ядре вместо прежнего объединения каналов.
- **Перезапущенная нода подхватывается сразу**: перезапущенный выход отвечает клиенту посреди сессии.

Полный список — в [CHANGELOG.md](CHANGELOG.md).

## Установка

Скачайте файл для своей системы на [странице релизов](../../releases/latest).

| Система | Файл |
|---|---|
| Windows 10/11 x64 | `.msi` или `-setup.exe` для установки, `-portable.zip` без установки |
| Linux x64 | `.deb` (Debian, Ubuntu, Mint) или `.tar.gz` |
| macOS | `-macos-arm64.dmg` (Apple silicon) или `-macos-x64.dmg` (Intel) |

- Сборки для macOS не подписаны: при первом запуске откройте приложение правым кликом → *Открыть*.
- Режиму «весь трафик» нужны права администратора (запрос UAC в Windows, пароль в macOS). В Linux направьте программы на прокси SOCKS5 `127.0.0.1:1080` или HTTP `127.0.0.1:1081`.

## Сборка из исходников

Нужны JDK 17 и Go (или Docker, чтобы собрать без Go).

```bash
git clone --recurse-submodules https://github.com/OpenFluxTeam/OpenFluxDesktop.git
cd OpenFluxDesktop
./gradlew :desktopApp:run          # запуск; при первом запуске собирает ядро для этой машины
```

Клонировали без `--recurse-submodules`? Выполните `git submodule update --init --recursive`.

| Команда | Что делает |
|---|---|
| `./gradlew :desktopApp:run` | запустить приложение |
| `scripts/build-core.sh` | собрать ядро вручную из сабмодуля `OpenFlux/` |
| `./gradlew :shared:jvmTest` | тесты |
| `./gradlew -PwindowsPackage=true :desktopApp:packageMsi` | Windows `.msi` (ещё `packageExe`) |
| `./gradlew :desktopApp:packageDmg` | macOS `.dmg` |
| `./gradlew :desktopApp:packageDeb` | Linux `.deb` (нужен `fakeroot`) |

Бинарники ядра в git не лежат: `run` и `package*` сами собирают ядро для этой машины в `desktopApp/resources/<windows|macos|linux>`, если его там нет. `-PskipCore=true` запускает приложение без ядра; тогда *Настройки → Ядро* принимает ваш файл.

## Устройство

```
desktopApp/   Окно, трей, горячие клавиши, упаковка
shared/       Сабмодуль: модели, сессии, настройки транспортов, мастер ноды, экраны
  jvmMain/
    core/     Запуск процесса ядра, статус по IPC, проверки Яндекса
    node/     Мастер ноды (ядро --node-wizard через stdin/stdout)
    web/      Встроенный браузер: KCEF вне экрана, роутер прокси, журнал
    platform/ Системный прокси Windows (WinInet), права администратора
    data/     Настройки, профили и установленные JS-транспорты
OpenFlux/     Сабмодуль: ядро (CLI), запускается подпроцессом
scripts/      build-core.sh
```

Клиент для Android — [OpenFluxAndroid](https://github.com/OpenFluxTeam/OpenFluxAndroid); оба используют модуль [OpenFluxClientShared](https://github.com/OpenFluxTeam/OpenFluxClientShared).
